## Data model (server enforces; the UI must explain, not duplicate, the rules)
- `users`: avatar (file, images, 2 MB, thumbs 64/100/256), cover (file, 5 MB, thumbs 400x133, 1200x400), headline, location, degree, linkedin_url, mentor, mentor_offer, role (alumnus|student|staff), tutor, tutor_subjects, `points` (read-only, server-written), `contact_mode` (open | points | request | closed, empty = open), `min_points` (0-10000), accepts_internship / accepts_mentoring / accepts_collab (bool). Members can read each other's users rows (authed only); `email` is hidden.
- `user_settings` {user unique, accent_hue 0-360 int, show_attendance}: owner only.
- `user_locations` {user unique, lat, lng, city, visible default FALSE}: readable by verified members only when visible = true (or own row); server snaps lat/lng to a 0.05 grid; the pin can move once per 24 h (1 h grace after creation); toggling visible is always allowed. Creating needs a verified email (magic-link sign-in verifies).
- `profiles_deep` {user unique, experience 2000, education 1000, skills 500, sectors 300, languages 200, offer 500, seek 500, link_linkedin (url), link_site (url), source (self|linkedin_import), visibility (members|private)}: written by the owner only; `is_sample` is never set by clients.
- `points_ledger` {user, delta, reason, ref, pair_key}: read own rows only, written by the server only. Points: a mentor/tutor earns 15 / 10 when THEY close an `active` mentorship that was active >= 24 h; one award per mentorship; same pair once per 7 days; no reciprocal farming; cap 15 per day. The mentee earns nothing. Contact rules use points (below). No spending in this round.
- `collab_requests` {from, to, kind (internship|mentoring|project|event|other), message <= 500, status (pending|accepted|declined)}: create as sender with status pending; only the recipient sets accepted/declined; the sender can delete a pending one; 10 per day; duplicate pending (from,to) rejected.
- `blocks` {blocker, blocked}: owner only.
- Contact doors (server hook, same message for every refusal): `messages`, `mentorships`, `collab_requests`, group invites. open = anyone; points = sender.points >= recipient.min_points; request = send a collaboration request first (messages denied until accepted); closed = nobody (replies to someone who wrote you first are always allowed). Show the rule in the UI before the user types; show the server message if it still refuses.
- `events` {title <= 120, description <= 2000, start (ISO date-time), end, city, lat/lng (server-snapped), place <= 120, host, hidden, going_count}: create needs a verified email, host = self, start within 12 months, end <= start + 14 days, max 3 per day; `rsvps` {event, user} unique, own rows only visible: show `going_count`, never attendee names.
- `conversations` {title <= 80, owner, members (max 12)} + `conversation_messages` {conversation, sender, text <= 2000}: members only; adds are checked against the invitee's contact rule; owner cannot leave (delete instead); `POST /api/uc/conversations/{id}/leave`; new members can read earlier messages (say so in the UI).
- `mentorships` + goals (<= 500), stage (goal|plan|sessions|done), next_session (date), active_at (server-stamped); a closed mentorship is frozen. `mentorship_docs` {mentorship, uploader, file (PROTECTED: pdf/png/jpeg/txt/docx, <= 10 MB), note <= 300}: participants only, only while the mentorship is `active`, max 30; deleted 90 days after the mentorship closes.
- Account deletion: `DELETE /api/collections/users/records/<own id>` removes the member and everything they own.
- `UC.state.user` is the signed-in `users` record; `UC.state.online` tells whether the API answered.
